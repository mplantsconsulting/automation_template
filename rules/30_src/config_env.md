# 設定と環境変数

| 項目 | 内容 |
| --- | --- |
| 対象 | 環境変数、設定ファイル、機能フラグなど、実行環境によって変わる値の扱い |
| レベル | 必須 |
| 最終更新 | 2026-09-10 |

## 目的

接続先や認証情報をコードに埋め込むと、環境ごとにコードを書き換える必要が生じ、秘密情報の漏洩にもつながる。
設定の読み込みがコード中に散らばると、どの値が必要か分からず、設定漏れが本番稼働中に初めて発覚する。
ここでは設定を 1 か所で読み、起動時に検証し、環境ごとに安全に切り替えるための基準を定める。

## ルール

### MUST

- 環境に依存する値(接続先 URL、認証情報、ファイルパス、ポート番号など)をソースコードに直接書かない。
- 環境変数や設定ファイルは起動時に 1 か所でまとめて読み込み、その結果を設定オブジェクトとして各層に渡す。処理の途中で環境変数を直接参照しない。
- 必須の設定が欠けていれば起動時に失敗させる。処理の途中で初めて参照して落ちる作りにしない。
- 設定値の型変換(文字列から数値、真偽値、リストなど)は読み込み層で行い、以降のコードは変換済みの値だけを扱う。
- `.env.example` をリポジトリに置き、必要な変数名と説明、ダミー値を記載する。実際の値を含む `.env` はコミットしない。
- 秘密情報(パスワード、API キー、トークン)は環境変数かシークレット管理サービスから渡し、設定ファイルにも書かない。

### SHOULD

- 環境(dev / stg / prod)の切り替えは、環境名を示す 1 つの変数(`APP_ENV` など)で行い、コード内で環境名による分岐を増やさない。
- デフォルト値は「安全側」に設定する。デバッグ無効、外部送信なし、最小権限など、忘れても事故にならない値を選ぶ。
- 秘密情報や環境固有の接続先にはデフォルト値を持たせない。欠けていたら失敗させる。
- 機能フラグ(feature flag)は設定オブジェクトの一部として扱い、参照箇所を限定する。不要になったフラグは分岐ごと削除する。
- 設定項目を追加・変更したら `.env.example` と README の該当箇所を同じ PR で更新する。

### MAY

- 設定の読み込み・検証には専用ライブラリを使ってもよい(スキーマ検証、型付き設定など)。
- 起動時に読み込んだ設定を、秘密情報をマスクした状態で INFO ログに出してもよい。

## Good / Bad 例

```text
# Bad: 接続先がコードに埋め込まれ、処理の途中で環境変数を直接参照している
def send_report():
    url = "https://api.example.com/v1"        # 環境ごとに書き換えが必要
    timeout = int(os.environ["TIMEOUT"])       # ここで初めて欠落に気づく
    ...

# Good: 起動時に 1 か所で読み、検証し、型変換した設定を渡す
# config.py(読み込み層)
def load_settings() -> Settings:
    return Settings(
        api_url=require_env("API_URL"),
        timeout_seconds=int(require_env("TIMEOUT_SECONDS")),
        debug=parse_bool(env_or_default("DEBUG", "false")),
    )
# main.py
settings = load_settings()                      # 欠けていればここで失敗
send_report(settings)
```

```text
# Bad: .env に実際の値を書いてコミットしている
.env
    API_KEY=sk-live-xxxxxxxxxxxx

# Good: .env.example に変数名と説明とダミー値だけを置く
.env.example
    APP_ENV=dev                    # dev / stg / prod
    API_URL=https://example.com    # 送信先 API のベース URL
    API_KEY=changeme               # 発行手順は README を参照
    TIMEOUT_SECONDS=30
```

```text
# Bad: 環境名による分岐がコードのあちこちにある
if env == "prod":
    url = PROD_URL
elif env == "stg":
    url = STG_URL

# Good: 環境ごとの差は設定値に閉じ込め、コードは設定を参照するだけ
url = settings.api_url
```

## チェックリスト

- [ ] 接続先、認証情報、パスなどがコードに直接書かれていないか
- [ ] 環境変数の読み込みが 1 か所にまとまっているか
- [ ] 必須の設定が欠けたとき起動時に失敗するか
- [ ] 設定値の型変換が読み込み層で完結しているか
- [ ] `.env.example` に追加・変更した変数が反映されているか
- [ ] `.env` や秘密情報を含むファイルがコミット対象から除外されているか
- [ ] 秘密情報にデフォルト値が設定されていないか
- [ ] 使われなくなった機能フラグと分岐が削除されているか

## 例外

- 環境によって変わらない定数(数学定数、固定のフォーマット文字列など)はコード内に定数として書いてよい。
- ローカル開発専用のデフォルト値(`localhost` の接続先など)は、`APP_ENV=dev` のときに限り持たせてよい。ただし本番環境で有効にならないことを確認する。
