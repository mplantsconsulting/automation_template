# ルール一覧

ルールのファイルと、読む場面の一覧です。このディレクトリ（`rules/`）を案件のリポジトリに写すと、この一覧も一緒に付いていきます。

| ファイル | 読む場面 |
| --- | --- |
| [general.md](general.md) | 常に。全体原則、命名、セキュリティ、標準ツール |
| [git.md](git.md) | 常に。ブランチ、コミット、Pull Request |
| [review.md](review.md) | PR をレビューするとき。観点の選び方、指摘の書き方、見た範囲 |
| [source.md](source.md) | 実装するとき。構成、関数、設定、エラー、ログ、コメント |
| [testing.md](testing.md) | テストを書くとき。方針、書き方、外部依存 |
| [docs.md](docs.md) | 文書を書くとき。Markdown、README、引き継ぎ |
| [frontend.md](frontend.md) | 画面を作るとき。技術選定、部品、状態、操作性 |
| [ci.md](ci.md) | CI を触るとき。Lint、Formatter、パイプライン |
| [infra.md](infra.md) | クラウドの構成をコードで書くとき。構成管理、データ、権限、テスト、デプロイ |
| [notion.md](notion.md) | Notion を使うとき。置き場所、ページ、タスク、見積と実績の入れ先 |
| [estimate.md](estimate.md) | 工数を見積もるとき、実績を入れるとき。見積の作り方、種別の振り分け、実績、基準の見直し |

AWS のアーキテクチャを設計、レビュー、実装するときは、上記に加えて [aws/AGENTS.md](../aws/AGENTS.md) と [aws/](../aws/) を読む。
AWS 固有の要件整理、設計判断、技術統制、自動検証、例外管理の正は `aws/` とする。
案件のリポジトリに `aws/` を写していない場合は、automation_template の `aws/` を読む。

各ファイルはテーマごとに節を作り、その中を強度で分けます。
新しいカテゴリを追加するときは [_template.md](_template.md) を使います。

| 表記 | 意味 |
| --- | --- |
| 必須 | 例外なく守る。違反はレビューで差し戻す |
| 推奨 | 原則守る。外す場合は理由を PR に書く |
| 任意 | 必要に応じて採用する |

「推奨」「任意」「例外」と明記した項目以外は必須です。
