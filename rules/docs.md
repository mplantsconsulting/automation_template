# ドキュメント

README、Markdown、引き継ぎ資料を短く再現可能な状態に保つ。

「推奨」「任意」「例外」と明記した項目以外は必須とする。

## Markdown

### 必須

- h1 はファイル冒頭に 1 つだけ置き、見出しレベルを飛ばさない。
- 見出しの前後に空行を置き、箇条書きは `-` に統一する。
- コードブロックに言語を指定し、画像には内容を表す代替テキストを書く。
- リポジトリ内は相対リンク、外部サイトは絶対 URL で参照する。

### 推奨

- 1 文を短くして 1 行に置き、行長は表と URL を除いて 120 文字以内を目安にする。
- 強調や装飾を増やさず、図は更新しやすい Mermaid を優先する。
- markdownlint などを CI で実行する。

## README

### 必須

- 冒頭で誰の何を解決するものかを説明する。
- 前提環境、セットアップ、実行、テストを独立した節にする。
- コマンドはコピーして実行できる形にし、置換箇所を `<...>` で示す。
- 設定と環境変数は用途と必須かどうかだけを書き、実値を書かない。
- 主要ディレクトリの役割と、チームまたは連絡先を書く。

### 推奨

- 手順は上から実行できる順序で書き、変更したら同じ PR で更新する。
- 詳細設計は `docs/`、変更履歴は `CHANGELOG.md` に分ける。
- [README の雛形](../templates/README_template.md)を使う。

## 引き継ぎ

- 必要な場合は `HANDOVER.md` をルートに置き、README からリンクする。
- 目的、現状、運用手順、既知の問題と回避策、未完了タスクを書く。
- アクセス権と秘密情報は所在と発行者だけを書き、値を書かない。

### 推奨

- 関係者の役割と重要な判断理由を残し、README と重複する説明はリンクにする。
- 引き継ぎ相手が資料だけで作業を再現できるか確認する。

## 例外

- 自動生成 Markdown は生成物と明記し、書式ルールの対象外にしてよい。
- GitHub の Issue や PR の front matter はツールの仕様を優先する。
