# Notion ワークスペースの構成

社内の Notion に今あるデータベースと列の一覧です。判断のルールは [rules/notion.md](../rules/notion.md) にあります。

この内容は Notion 側を変えると古くなります。食い違いを見つけたら、Notion ではなくこのファイルを直してください。

最終確認日は 2026-11-24 です。

## 階層

```text
ワークスペース
└─ Operations                      全データベースを置く親ページ
   ├─ 🏢 クライアント              取引先。1 社 1 行
   │  └─ 🚀 プロジェクト           案件。1 案件 1 行
   │     ├─ ✅ タスク              作業。1 作業 1 行
   │     ├─ 🗂 リポジトリ          コード。1 リポジトリ 1 行
   │     │  └─ 🐛 Issue/PR         GitHub から自動同期
   │     └─ ⚠️ インシデント        障害と対応。1 件 1 行
   ├─ 👥 メンバー                  担当者。プロジェクトとタスクから参照
   └─ 全社ダッシュボード           KPI の集計ビュー。閲覧専用
```

## 各データベースの使い分け

| データベース | 1 行の単位 | 親 | 必ず埋める |
| --- | --- | --- | --- |
| 🏢 クライアント | 取引先 1 社 | なし | 会社名、ステータス、業界 |
| 🚀 プロジェクト | 案件 1 件 | クライアント | プロジェクト名、クライアント、ステータス、開始日、PM または開発担当 |
| ✅ タスク | 作業 1 件 | プロジェクト | タスク名、プロジェクト、ステータス、見積工数h（親タスクのみ）、実績工数h（子タスクの完了時） |
| 🗂 リポジトリ | GitHub リポジトリ 1 つ | プロジェクト | リポジトリ名、フルネーム、関連プロジェクト |
| 🐛 Issue/PR | Issue または PR 1 件 | リポジトリ | 自動同期のため手入力しない |
| ⚠️ インシデント | 障害 1 件 | プロジェクト | タイトル、発生日、カテゴリ、原因、対応・解決方法 |
| 👥 メンバー | 人 1 名 | なし | 氏名、役職、在籍状況 |

| データベース | 列 | 値 |
| --- | --- | --- |
| プロジェクト | ステータス | 保留 / 要件定義中 / PoC / 進行中 / テスト中 / 完了 / 中止 / エラー対応中 |

## 工数の列

見積は親タスクに、実績は子のないタスクに入れます（[rules/notion.md](../rules/notion.md) の「見積」）。
どちらも手を動かした時間だけを数え、先方を待つ時間は入れません。

| データベース | 列 | 種類 | 中身 |
| --- | --- | --- | --- |
| タスク | `見積工数h` | 数値 | 親タスクだけに入れる |
| タスク | `実績工数h` | 数値 | 子のないタスクだけに、完了時に入れる。子のない親は親に入れる |
| タスク | `工数区分` | 選択 | 開発 / PM。開発と PM の集計を分ける |
| タスク | `タスク種別` | 選択 | 任意。子タスクに付ける。選択肢は[見積の基準](estimate-baseline.md)の種別と同じ |
| プロジェクト | `予想開発時間` | 数値 | 親の見積の合計。`project-estimate` が入れる |
| プロジェクト | `見積工数合計h` | ロールアップ | 全タスクの `見積工数h` の合計。親だけに入れるので、親の合計と同じになる |
| プロジェクト | `実績工数合計h` | ロールアップ | 全タスクの `実績工数h` の合計 |
| プロジェクト | `開発見積工数合計h`、`PM見積工数合計h` | ロールアップ | `工数区分` ごとの見積の合計 |
| プロジェクト | `開発実績工数合計h`、`PM実績工数合計h` | ロールアップ | `工数区分` ごとの実績の合計 |
| プロジェクト | `見積乖離率` | 数式 | `(開発実績工数合計h − 予想開発時間) ÷ 予想開発時間` |

タスクには、子の値を親へ集計する列はありません。親ごとの実績は `project-estimate` が子から計算します。

## 自動更新される列

GitHub からの同期スクリプトが書き込みます。手で編集しても次回の同期で上書きされます。

| 列 | 対象 |
| --- | --- |
| `最新PR`、`最新PRリンク`、`最新PR状態`、`最新PR更新日時` | リポジトリ、プロジェクト |
| `最終同期日時` | リポジトリ |
| すべての列 | Issue/PR |

同期は `フルネーム`（`owner/name`）で行を突き合わせます。同じ値で行を作れば、次回の同期は重複を作らず更新します。

## 既知の癖

| 症状 | 内容 |
| --- | --- |
| 優先度が `中` に戻る | オートメーションが作成の約 5 秒後に上書きする。作成応答は上書き前の値を返すため、その場では気づけない |
| Issue/PR のリレーションが付かない | GitHub からの同期は毎時。PR を作った直後は行が存在しない |
| ブロックが作れない | `child_database` は API で作成できない。インラインビューの設置は Notion の画面で行う |
| 完了した親タスクに「📝実績工数未入力」が出る | アラートの式が親と子を区別しない。子のある親には実績を入れないので無視する。子のない親なら実績を入れる |
