# Notion ワークスペースの構成

社内の Notion に今あるデータベースと列の一覧です。判断のルールは [rules/notion.md](../rules/notion.md) にあります。

この内容は Notion 側を変えると古くなります。食い違いを見つけたら、Notion ではなくこのファイルを直してください。

最終確認日は 2026-09-15 です。

## 階層

```text
ワークスペース
└─ Operations                      全データベースを置く親ページ
   ├─ 🏢 クライアント              取引先。1 社 1 行
   │  └─ 🚀 プロジェクト           案件。1 案件 1 行
   │     ├─ ✅ タスク              作業。1 作業 1 行
   │     ├─ 🗂 リポジトリ          コード。1 リポジトリ 1 行
   │     │  └─ 🐛 Issue/PR         GitHub から自動同期
   │     └─ ⚠️ インシデント        障害と対応。1 件 1 行
   ├─ 👥 メンバー                  担当者。プロジェクトとタスクから参照
   └─ 全社ダッシュボード           KPI の集計ビュー。閲覧専用
```

## 各データベースの使い分け

| データベース | 1 行の単位 | 親 | 必ず埋める |
| --- | --- | --- | --- |
| 🏢 クライアント | 取引先 1 社 | なし | 会社名、ステータス、業界 |
| 🚀 プロジェクト | 案件 1 件 | クライアント | プロジェクト名、クライアント、ステータス、開始日、PM または開発担当 |
| ✅ タスク | 作業 1 件 | プロジェクト | タスク名、プロジェクト、ステータス、見積工数h（子タスクのみ） |
| 🗂 リポジトリ | GitHub リポジトリ 1 つ | プロジェクト | リポジトリ名、フルネーム、関連プロジェクト |
| 🐛 Issue/PR | Issue または PR 1 件 | リポジトリ | 自動同期のため手入力しない |
| ⚠️ インシデント | 障害 1 件 | プロジェクト | タイトル、発生日、カテゴリ、原因、対応・解決方法 |
| 👥 メンバー | 人 1 名 | なし | 氏名、役職、在籍状況 |

## 主な選択肢

| データベース | 列 | 値 |
| --- | --- | --- |
| プロジェクト | ステータス | 保留 / 未着手 / 進行中 / 中止 / 完了 |
| プロジェクト | ショット/ランニング | ショット / ランニング / その他 |
| タスク | ステータス | 保留 / 未着手 / 進行中 / レビュー / 完了 |
| タスク | 工数区分 | 開発 / PM |
| 共通 | 優先度 | 高 / 中 / 低 |

## 自動更新される列

GitHub からの同期スクリプトが書き込みます。手で編集しても次回の同期で上書きされます。

| 列 | 対象 |
| --- | --- |
| `最新PR`、`最新PRリンク`、`最新PR状態`、`最新PR更新日時` | リポジトリ、プロジェクト |
| `最終同期日時` | リポジトリ |
| すべての列 | Issue/PR |

同期は `フルネーム`（`owner/name`）で行を突き合わせます。同じ値で行を作れば、次回の同期は重複を作らず更新します。

## 既知の癖

| 症状 | 内容 |
| --- | --- |
| 優先度が `中` に戻る | オートメーションが作成の約 5 秒後に上書きする。作成応答は上書き前の値を返すため、その場では気づけない |
| Issue/PR のリレーションが付かない | GitHub からの同期は毎時。PR を作った直後は行が存在しない |
| ブロックが作れない | `child_database` は API で作成できない。インラインビューの設置は Notion の画面で行う |
