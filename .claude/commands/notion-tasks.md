プロジェクト `$1` の親タスクを子タスクへ分解し、Notion に登録する。

親タスクと見積は `/notion-project` で作ってある前提で進める。子タスクには見積を入れない。
ルールは [rules/notion.md](../../rules/notion.md) と [rules/git.md](../../rules/git.md) に従う。

## 命名

| 段 | 形式 | 例 | 見積工数 |
| --- | --- | --- | --- |
| 親 | `N. 機能のまとまり` | `2. AI読込・情報抽出機能開発` | `/notion-project` で入れてある |
| 子 | `N-M. 具体的な作業` | `2-1. 処理済み案件の再処理防止` | 入れない |

子の番号は親の番号に揃える。番号だけで実施順序が分かるようにする。

## 手順

### 1. 現状を読む

1. `node scripts/notion.mjs project-get $1` でプロジェクトと既存タスクを取得する。`isParent` が `true` のものが親タスク。
2. 親タスクが無い場合、または見積の入っていない親がある場合は、その場で止める。先に `/notion-project` の「親タスクを作り、見積を入れる」を行うよう伝える。
3. `$2` があればその資料を読む。なければプロジェクトページ本文、親タスクの本文、リポジトリの README を読む。

### 2. 子タスクを作る

4. 親ごとに作業を分ける。次を守る。

   - **1 子タスクが 1 PR に対応する粒度にする。** PR の差分が 300 行を超えそうなら分ける。
   - 学習・調査だけの子タスクは、成果物(判断、資料、方針)を名前に含める。
   - 既存タスクと重複するものは作らない。
   - 1 つの親に子が 6 件を超える場合は、親の分け方を見直す。

5. 各子タスクに次を決める。

   | 項目 | 引数 | 既定 |
   | --- | --- | --- |
   | タスク名 | `--name` | `N-M. ` で始める。動詞で終える |
   | 親タスク | `--parent` | 必須。親の `TSK-000` |
   | 工数区分 | `--kind` | 開発 / PM |
   | タスク種別 | `--type` | 任意。[reference/estimate-baseline.md](../../reference/estimate-baseline.md) の種別から 1 つ選ぶ。作り直しや手戻りは「修正・手戻り」。迷う場合は省く |
   | 優先度 | `--priority` | 高 / 中 / 低 |
   | 担当者 | `--assignee` | 未定なら省く |
   | 期日 | `--due` | プロジェクトの予定終了日を超えない |

   ```bash
   node scripts/notion.mjs task-create --project $1 --parent TSK-000 \
     --name "1-1. 保管先の接続実装" --kind 開発 --type "バック（外部連携）" --priority 高
   ```

6. 登録前に、親ごとにまとめた一覧を表で示す。列は タスク名、工数区分、タスク種別、優先度、担当者、期日 とし、親ごとに親の見積工数を添える。
7. 分けてみて親の見積が明らかに足りない、または余ると分かった場合は、登録前に指摘する。親の見積を直すかは利用者が決める。
8. **利用者の確認を取ってから** 登録する。
9. 親ごとに本文の「進め方」「子タスク」「現在地」を書き足す。見出しと書く内容は [rules/notion.md](../../rules/notion.md) の「親タスク」に従う。子タスクはページメンションで並べる。本文も**利用者に見せてから**書き込む。
10. 登録後、親と子の構造を報告し、次に `/task-pr TSK-000` を実行できることを伝える。

## 注意

- 子タスクに `--estimate` を付けると `task-create` が止まる。
- 親の見積を直した場合は、同じ日に `node scripts/notion.mjs project-estimate $1` で `予想開発時間` を入れ直す。
- 優先度は登録の数秒後に Notion のオートメーションが `中` へ戻す。`--priority` の指定は残らない。残したい場合だけ `NOTION_VERIFY_DELAY_MS=8000` を付けて実行する。1 件あたり 10 秒前後かかる。
- ステータスは既定の `未着手` のままにする。着手時に `/task-pr` が更新する。
