案件資料 `$1` を読み、Notion のプロジェクトを 1 件作る。続けて親タスクを作り、親ごとに見積を入れる。

ルールは [rules/notion.md](../../rules/notion.md) に従う。見積の決め方は同じファイルの「見積」、種別と基準の値は [reference/estimate-baseline.md](../../reference/estimate-baseline.md) にある。必ず埋める項目は [reference/notion-workspace.md](../../reference/notion-workspace.md) の「各データベースの使い分け」にある。

## 手順

### 1. プロジェクトを作る

1. `$1` を読む。パスが省略された場合は、リポジトリ内の要件定義や提案資料を探して候補を示し、どれを使うか聞く。
2. 資料から次を読み取る。読み取れない項目は推測せず、後で聞く。

   | 項目 | 引数 | 補足 |
   | --- | --- | --- |
   | プロジェクト名 | `--name` | 資料の表題ではなく、案件を識別できる名前にする |
   | クライアント | `--client` | `$2` があれば優先する |
   | PM | `--pm` | 資料に記載がなければ聞く |
   | 開発担当 | `--dev` | 複数はカンマ区切り |
   | レビュワー | `--reviewer` | 任意 |
   | 開始日 | `--start` | 省略時は今日 |
   | 予定終了日 | `--due` | 資料に納期があれば入れる |
   | 優先度 | `--priority` | 高 / 中 / 低 |
   | ショット / ランニング | `--kind` | 継続課金なら ランニング |
   | リポジトリ | `--repo` | 既存リポジトリがあれば紐付ける |

3. クライアント名とメンバー名は Notion の登録名と一致させる。曖昧なら `node scripts/notion.mjs clients` と `node scripts/notion.mjs members` で確認する。
4. 不足している必須項目(プロジェクト名、クライアント、PM または開発担当)をまとめて 1 度だけ聞く。
5. `--dry-run` を付けて実行し、作られる内容を表形式で示す。
6. **利用者の確認を取ってから** `--dry-run` を外して実行する。Notion は共有ワークスペースであり、作成後の取り消しに手間がかかる。
7. 作成された `PJ-000` と URL を控える。

### 2. 親タスクを作り、見積を入れる

8. 資料から機能のまとまりを洗い出し、**親タスクをいくつ作るかを利用者に聞く。** 聞かずに決めない。
   候補と、それぞれに何が入るかを 1 行で添えて示す。
9. 聞いた数に合わせてまとまりを統合または分割し、実施順に `1.` から番号を振る。名前は `N. 機能のまとまり` にする。
10. 親ごとに見積を作る。手順は [rules/notion.md](../../rules/notion.md) の「見積」に従う。

    - 工程のチェックリストを上から確かめ、要る工程の作業を拾う。要らない工程は理由を 1 行で書く。
    - 親の名前、目的、案件資料だけで考える。子タスクはまだ無く、あっても中身から種別や数を拾わない。
    - 作業を種別に分け、基準の単位で数を見込む。見込んだ中身を列挙する。レビュー（実装）の本数は、作りそうな PR の本数で見込む。
    - 基準の楽観、標準、悲観を出発点に、その親の事情で上げ下げし、理由を 1 行で書く。基準のままなら「基準どおり」と書く。
    - 項目ごとに小計とばらつきを出し、小計の合計を見積工数にする。あわせて 85% の値を出す。小数第 1 位までにする。
    - 先方を待つ時間は入れない。待ちは「進め方」と「決定事項と未決事項」に書く。
    - 基準にない種別の作業があれば、推測で埋めず、手順 11 で一緒に聞く。

11. 登録前に、親ごとの内訳と見積工数、85% の値、要らない工程を表で示す。プロジェクト全体の平均と 85% の値も示す。基準にない作業があれば、ここでまとめて聞く。
12. **利用者の確認を取ってから** 親タスクを登録する。

    ```bash
    node scripts/notion.mjs task-create --project PJ-000 --name "1. データ取得・投入基盤構築" \
      --estimate 24 --kind 開発 --priority 高
    ```

13. 親ごとに本文を作る。「目的」「見積」「決定事項と未決事項」を書く。見出しと書く内容は [rules/notion.md](../../rules/notion.md) の「親タスク」に従う。本文は Markdown のファイルに書き、**利用者に見せてから** `body-set` で書き込む。

    ```bash
    node scripts/notion.mjs body-set TSK-000 --md <本文のパス>
    ```

14. 親の見積の合計をプロジェクトの `予想開発時間` に入れる。

    ```bash
    node scripts/notion.mjs project-estimate PJ-000
    ```

15. プロジェクトと親タスクの番号、見積の平均と 85% の値を報告し、先方に伝えるときは 85% の値を使うよう添える。そのうえで次に `/notion-tasks PJ-000` を実行できることを伝える。

## 注意

- 資料本文はプロジェクトページの本文へ入る。`--md $1` を付けると資料をそのまま本文にする。
- 同名のプロジェクトが既にある場合は作らず、既存のものを示す。`project-create` は同名を見つけると `--dry-run` でもエラーで止まり、既存の番号と URL を出す。
- ステータスは指定しなければ Notion の既定値になる。指定するときは [reference/notion-workspace.md](../../reference/notion-workspace.md) の値から選ぶ。
- 数値(売上、コスト)は資料に明記されている場合だけ入れる。推測で埋めない。
- 親タスクの `--estimate` は必須。無いと `task-create` が止まる。
- 優先度は登録の数秒後に Notion のオートメーションが `中` へ戻す。残したい場合だけ `NOTION_VERIFY_DELAY_MS=8000` を付けて実行する。
