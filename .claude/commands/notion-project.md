argument-hint: <案件資料のパス> [クライアント名]
allowed-tools: Read, Glob, Grep, Write, Bash(node scripts/notion.mjs:*)
---

案件資料 `$1` から、Notion のプロジェクトを 1 件作り、削減時間を見積もり、親タスクの目的を書いてから見積を入れる。

一気に作らず、利用者と 4 往復して進める。1 往復で扱うテーマは 1 つにし、AI が出すものを見せてから、質問はその往復の中で 1 回にまとめて聞く。Notion へ書き込むのは、往復 2 と 4 の承認の後だけにする。

| 往復 | テーマ | 書き込み |
| --- | --- | --- |
| 1 | 要件の理解 | なし |
| 2 | プロジェクトと削減時間 | プロジェクト、削減時間 |
| 3 | 親タスクと目的 | なし |
| 4 | 見積 | 親タスク、本文、予想開発時間 |

ルールは [rules/notion.md](../../rules/notion.md) に従う。見積と削減時間の決め方は [rules/estimate.md](../../rules/estimate.md)、種別と基準の値は [reference/estimate-baseline.md](../../reference/estimate-baseline.md) にある。必ず埋める項目は [reference/notion-workspace.md](../../reference/notion-workspace.md) の「各データベースの使い分け」にある。

## 往復 1. 要件の理解

AI の理解を先に書いて見せ、ずれと抜けを利用者に直してもらう。

1. `$1` を読む。パスが省略された場合は、リポジトリ内の要件定義や提案資料を探して候補を示し、どれを使うか聞く。
2. 次の見出しごとに、資料をどう理解したかを短くまとめる。資料に書かれていない見出しは「記載なし」と書く。

   | 見出し | まとめる内容 |
   | --- | --- |
   | 背景 | 今どうなっているか。件数や時間 |
   | 課題 | 何が困っているか |
   | やりたいこと | 実現したいこと |
   | スコープ / スコープ外 | やること / やらないこと |
   | 規模 | 自動化する業務ごとの月の回数、1 回の時間。画面、帳票、連携先、移す既存の処理の数 |
   | 前提 | データの置き場所、利用者、制約 |

3. 次の項目のうち、資料に無いもの、曖昧なものを洗い出す。推測で埋めない。

   - プロジェクトの必須項目：プロジェクト名、クライアント、PM または開発担当（往復 2 の表を参照）
   - 削減時間に要る数：自動化する業務ごとの月の回数、自動化前の 1 回の時間、自動化後に残る作業と時間、運用の月の時間
   - スコープ外と規模。空のままだと、往復 3 と 4 でタスクと見積が抜ける

4. まとめと質問を 1 つのメッセージで示し、利用者の答えを待つ。質問はここで 1 回にまとめる。

## 往復 2. プロジェクトと削減時間

5. 往復 1 の答えを入れて、プロジェクトの項目を埋める。

   | 項目 | 引数 | 補足 |
   | --- | --- | --- |
   | プロジェクト名 | `--name` | 資料の表題ではなく、案件を識別できる名前にする |
   | クライアント | `--client` | `$2` があれば優先する |
   | PM | `--pm` | |
   | 開発担当 | `--dev` | 複数はカンマ区切り |
   | レビュワー | `--reviewer` | 任意 |
   | 開始日 | `--start` | 省略時は今日 |
   | 予定終了日 | `--due` | 資料に納期があれば入れる |
   | 優先度 | `--priority` | 高 / 中 / 低 |
   | ショット / ランニング | `--kind` | 継続課金なら ランニング |
   | リポジトリ | `--repo` | 既存リポジトリがあれば紐付ける |

   クライアント名とメンバー名は Notion の登録名と一致させる。曖昧なら `node scripts/notion.mjs clients` と `node scripts/notion.mjs members` で確認する。

6. `--dry-run` で作られる内容を出す。

   ```bash
   node scripts/notion.mjs project-create \
     --name "<プロジェクト名>" --client "<会社名>" --pm "<氏名>" --dev "<氏名>" \
     --start 2026-10-01 --due 2026-12-31 --priority 中 --kind ショット \
     --md $1 --dry-run
   ```

7. 削減時間の内訳を作る。業務ごとに `月の回数 × (自動化前の 1 回 − 自動化後の 1 回)` を出し、運用を行として足す。決まりは [rules/estimate.md](../../rules/estimate.md) の「削減時間の見積」、表の形は [reference/estimate-baseline.md](../../reference/estimate-baseline.md) の「削減時間の内訳の例」に従う。
8. プロジェクトの表と削減時間の表を 1 つのメッセージで示し、直すところがないかを聞く。
9. **利用者の承認を取ってから**書き込む。Notion は共有ワークスペースであり、作成後の取り消しに手間がかかる。

   ```bash
   node scripts/notion.mjs project-create ...                 # 手順 6 から --dry-run を外す
   node scripts/notion.mjs project-savings PJ-000 --before 46 --after 9
   node scripts/notion.mjs body-set PJ-000 --md <削減時間の見積の節のパス> --append
   ```

10. 作られた `PJ-000` と URL、月の削減時間を報告する。削減時間は、完了するまで概算であることを添える。

## 往復 3. 親タスクと目的

親タスクの候補と目的を見せ、分け方と範囲を利用者に直してもらう。見積はまだ作らない。

11. 資料から機能のまとまりを洗い出し、親タスクの候補を作る。実施順に `1.` から番号を振り、名前は `N. 機能のまとまり` にする。
12. 親ごとに「目的」を書く。書く内容は [rules/notion.md](../../rules/notion.md) の「親タスク」に従う。範囲（何を、いくつ）は往復 1 の「規模」から取る。
13. [reference/estimate-baseline.md](../../reference/estimate-baseline.md) の工程のチェックリストを見て、抜けていそうな作業（設計、結合確認、リリース・引き継ぎ、説明資料など）と、スコープ外に当たりそうな作業を挙げる。
14. 候補、目的、抜けと余分の指摘を 1 つのメッセージで示し、**親の数と分け方、範囲を利用者に決めてもらう。** 聞かずに決めない。ここで直した範囲が、そのまま往復 4 の見積の入力になる。

## 往復 4. 見積

15. 往復 3 で確認した親の名前と目的だけを見て、親ごとに見積を作る。決まりは [rules/estimate.md](../../rules/estimate.md)、種別と値は [reference/estimate-baseline.md](../../reference/estimate-baseline.md) に従う。目的に書いていない作業が要ると気づいたら、見積に足さずに、範囲を足すかを利用者に聞く。
16. 親ごとの内訳、見積工数、85% の値、要らない工程と、プロジェクト全体の平均と 85% の値を 1 つのメッセージで示す。基準にない作業があれば、ここでまとめて聞く。
17. **利用者の承認を取ってから**書き込む。親ごとに、親タスクを見積と一緒に作り、本文に往復 3 の「目的」、往復 4 の「見積」、「決定事項と未決事項」を書く。見出しは [rules/notion.md](../../rules/notion.md) の「親タスク」に従う。最後に、親の見積の合計を `予想開発時間` に入れる。

    ```bash
    node scripts/notion.mjs task-create --project PJ-000 --name "1. データ取得・投入基盤構築" \
      --estimate 24 --kind 開発 --priority 高
    node scripts/notion.mjs body-set TSK-000 --md <本文のパス>
    node scripts/notion.mjs project-estimate PJ-000
    ```

18. プロジェクトと親タスクの番号、見積の平均と 85% の値を報告し、先方に伝えるときは 85% の値を使うよう添える。そのうえで次に `/notion-tasks PJ-000` を実行できることを伝える。

## 注意

- 資料本文はプロジェクトページの本文へ入る。`--md $1` を付けると資料をそのまま本文にする。削減時間の見積は、本文を消さないよう `body-set --append` で末尾へ足す。
- 同名のプロジェクトが既にある場合は作らず、既存のものを示す。`project-create` は同名を見つけると `--dry-run` でもエラーで止まり、既存の番号と URL を出す。
- ステータスは指定しなければ Notion の既定値になる。指定するときは [reference/notion-workspace.md](../../reference/notion-workspace.md) の値から選ぶ。
- 数値(売上、コスト)は資料に明記されている場合だけ入れる。推測で埋めない。
- 親タスクの `--estimate` は必須。無いと `task-create` が止まる。
- 優先度は登録の数秒後に Notion のオートメーションが `中` へ戻す。残したい場合だけ `NOTION_VERIFY_DELAY_MS=8000` を付けて実行する。
