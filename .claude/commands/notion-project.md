argument-hint: <案件資料のパス> [クライアント名]
allowed-tools: Read, Glob, Grep, Bash(node scripts/notion.mjs:*)
---

案件資料 `$1` を読み、Notion のプロジェクトを 1 件作る。

ルールは [rules/notion.md](../../rules/notion.md) の「各データベースの使い分け」に従う。

## 手順

1. `$1` を読む。パスが省略された場合は、リポジトリ内の要件定義や提案資料を探して候補を示し、どれを使うか聞く。
2. 資料から次を読み取る。読み取れない項目は推測せず、後で聞く。

   | 項目 | 引数 | 補足 |
   | --- | --- | --- |
   | プロジェクト名 | `--name` | 資料の表題ではなく、案件を識別できる名前にする |
   | クライアント | `--client` | `$2` があれば優先する |
   | PM | `--pm` | 資料に記載がなければ聞く |
   | 開発担当 | `--dev` | 複数はカンマ区切り |
   | レビュワー | `--reviewer` | 任意 |
   | 開始日 | `--start` | 省略時は今日 |
   | 予定終了日 | `--due` | 資料に納期があれば入れる |
   | 優先度 | `--priority` | 高 / 中 / 低 |
   | ショット / ランニング | `--kind` | 継続課金なら ランニング |
   | リポジトリ | `--repo` | 既存リポジトリがあれば紐付ける |

3. クライアント名とメンバー名は Notion の登録名と一致させる。曖昧なら `node scripts/notion.mjs clients` と `node scripts/notion.mjs members` で確認する。
4. 不足している必須項目(プロジェクト名、クライアント、PM または開発担当)をまとめて 1 度だけ聞く。
5. `--dry-run` を付けて実行し、作られる内容を表形式で示す。
6. **利用者の確認を取ってから** `--dry-run` を外して実行する。Notion は共有ワークスペースであり、作成後の取り消しに手間がかかる。
7. 作成された `PJ-000` と URL を報告し、次に `/notion-tasks PJ-000` を実行できることを伝える。

## 注意

- 資料本文はプロジェクトページの本文へ入る。`--md $1` を付けると資料をそのまま本文にする。
- 同名のプロジェクトが既にある場合は作らず、既存のものを示す。
- 数値(売上、コスト、工数)は資料に明記されている場合だけ入れる。推測で埋めない。
