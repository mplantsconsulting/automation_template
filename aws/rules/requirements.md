# AWS 設計の要件

AWS サービスを選ぶ前に、設計判断と検証に必要な要件を構造化する。

「推奨」「任意」「例外」と明記した項目以外は必須とする。

## 分類

### 必須

- 要件を次の 5 種類に分け、一意な ID を付ける。

| 接頭辞 | 分類 | 内容 |
| --- | --- | --- |
| `BR` | ビジネス要件 | 導入によって達成したい成果 |
| `FR` | 機能要件 | システムが提供する振る舞い |
| `NFR` | 非機能要件 | 性能、可用性、復旧、保護、運用、費用などの品質 |
| `CON` | 制約 | 変更できない契約、既存資産、技術、地域などの条件 |
| `ASM` | 仮定 | 未確認だが比較設計を進めるために一時的に置く条件 |

- 仮定を承認済み要件として扱わない。
- 出典、責任者、状態、優先度、検証方法を記録する。
- 数値を推測で補わず、不明なら未決事項にする。
- 要件が変わった場合は、関連する ADR、リソース、試験への影響を確認する。

## ビジネス要件

### 必須

- 誰のどの問題を解決するかと、成功を判断する方法を確認する。
- 利用者、利用地域、利用時間、業務停止時の影響を確認する。
- 初期費用、継続費用、利用増加時の許容条件を確認する。
- PoC、検証、本番の区別と期限を確認する。
- 開発、運用、セキュリティ、費用、承認の責任者を確認する。
- 既存 AWS、他クラウド、オンプレミス、契約、規制、データ所在地を確認する。

### 任意

- 組織で重要度分類を定めている場合は記録してよい。ただし、重要度だけで Multi-AZ、マルチリージョン、サービスを決めない。

## 機能要件

### 必須

- Actor、Trigger、Input、Processing、Output を記録する。
- 状態遷移とトランザクションの境界を記録する。
- 失敗、タイムアウト、再試行、取消、補償の扱いを記録する。
- 重複実行、順序、同時実行の扱いを記録する。
- 実行権限、外部依存、受入条件を記録する。

## 非機能要件

### 必須

- 次のうち該当する項目を確認し、測定条件と合格条件を記録する。

| 領域 | 確認内容 |
| --- | --- |
| 性能 | 応答時間、処理量、バッチ完了時間、同時実行 |
| 容量 | 初期量、増加率、保存期間、最大サイズ |
| 可用性 | 提供時間、SLO、計画停止、障害時の許容状態 |
| 復旧 | RTO、RPO、復旧対象、復旧試験 |
| 拡張性 | 負荷の変化、拡張単位、上限、クォータ |
| セキュリティ | データ分類、認証、認可、監査、脅威 |
| 運用 | 検知時間、通知先、対応時間、Runbook、保守体制 |
| 費用 | 予算条件、対象環境、通常・ピーク・成長時の前提 |
| データ保護 | 保存、削除、バックアップ、暗号鍵、データ所在地 |
| 継続性 | 依存先停止時の挙動、縮退、保留、再処理 |

- `p95` などの統計値には、測定区間、負荷、データ条件、測定地点を付ける。
- RTO と RPO には対象障害と対象データを付ける。
- 費用には含む環境、利用量、稼働時間、料金条件を付ける。

## 未決事項

### 必須

- 未決事項ごとに、設計への影響、確認先、責任者、期限を記録する。
- 重大な未決事項が残る場合は、比較設計は行っても本番構成を承認済みとして扱わない。
- 未決事項を埋めるための仮定には、影響する設計判断と失効条件を付ける。

## Gate 1

### 必須

次を満たすまで要件完了にしない。

- 主要な機能要件に ID と受入条件がある。
- 性能、負荷、復旧、セキュリティ、運用、費用の該当要件を確認している。
- 制約と仮定が要件から分離されている。
- 重大な未決事項が明示されている。
- 必須要件の責任者と検証方法が決まっている。
- 要件の承認者が内容を確認している。

## 例外

- PoC では未確定の非機能要件を仮定として進めてよい。ただし、本番利用前に Gate 1 を再実行する。
