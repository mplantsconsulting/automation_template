# AWS サービス選定の確認項目

AWS サービスの候補を絞るための参考資料です。必須ルールではありません。
サービスの仕様、クォータ、提供リージョン、料金は変わるため、採用前に AWS 公式資料で確認します。

最終確認日は 2026-11-13 です。

## 共通

サービス名を挙げる前に次を確認します。

- 対応する要件 ID
- 入力、出力、状態、データ量
- 通常時、ピーク時、成長時の負荷
- 許容する停止、RTO、RPO
- 公開範囲、データ分類、認証、認可
- 再試行、重複、順序、タイムアウト
- クォータ、リージョン、サービス制限
- チームが運用できる範囲
- 初期、継続、データ転送、監視の費用条件
- 移行と撤退の方法

## コンピュート

### 確認する特性

| 項目 | 確認内容 |
| --- | --- |
| 実行形態 | リクエスト、イベント、定期、常駐 |
| 実行時間 | 最大時間、タイムアウト、再開方法 |
| 負荷 | 一定、周期、突発、最大並列数 |
| 環境 | 言語、OS、コンテナ、ネイティブ依存 |
| 状態 | ステートレス、ローカル状態、共有状態 |
| 特殊要件 | GPU、特権操作、固定経路 |
| 運用 | デプロイ、パッチ、スケール、障害調査 |

### 比較候補

- Lambda：イベント処理、短時間処理、変動負荷
- ECS Fargate：コンテナ、常駐 API、長時間ジョブ
- AWS Batch：大規模または計算資源を調整するバッチ
- EC2：特殊 OS、GPU、ホスト制御、既存ソフトウェア
- EKS：Kubernetes が組織標準で、その運用能力がある場合

これは採用表ではありません。実行時間、負荷、制限、運用能力、費用を比較します。

## データストア

### 確認する特性

- リレーショナル、Key-Value、文書、オブジェクト、検索、時系列などのデータモデル
- 主キー検索、範囲検索、JOIN、集計などのアクセスパターン
- トランザクション、更新競合、整合性
- 初期量、増加率、保持期間、読み書きの比率
- 接続数、レイテンシ、ピーク負荷
- バックアップ、復元、移行、バージョン更新

### 比較候補

- RDS：リレーショナルモデル、SQL、トランザクション
- Aurora：互換性を保ちながら、要件に合う可用性やスケーリングを比較する場合
- DynamoDB：キー中心のアクセスとスケール特性が合う場合
- S3：ファイル、画像、成果物、データレイクなどのオブジェクト
- OpenSearch Service：検索機能や検索向け分析
- Redshift など：分析用の列指向データウェアハウス

DB を決める前に、アクセスパターンと整合性を確定します。

## 同期と非同期

即時の結果が必要か、処理時間、負荷変動、再試行、呼び出し元との結合度を確認します。

非同期処理では、サービスを決める前に次を設計します。

- 配信保証
- 順序保証
- 重複排除と冪等性
- 再試行回数、間隔、バックオフ
- DLQ とリプレイ
- 処理時間と可視性タイムアウト
- 滞留件数と最古メッセージの監視

候補には SQS、SNS、EventBridge、Step Functions、ストリーミングサービスなどがあります。
イベント通知、作業キュー、ワークフロー、ストリームを同じものとして扱いません。

## ネットワーク

VPC を使うかではなく、接続先、公開範囲、固定経路、通信制御、データ転送から判断します。

- インターネットからの入口
- AWS サービスへの出口
- オンプレミス、他アカウント、他リージョンとの接続
- NAT Gateway と VPC Endpoint の必要性
- AZ 間・リージョン間の通信量
- CIDR の重複と将来接続
- DNS、証明書、名前解決
