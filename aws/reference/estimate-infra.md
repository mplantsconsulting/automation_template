# インフラ見積のレベルとブロック

AWS の案件で、見積の種別「インフラ（構築・L1）〜（構築・L3）」を選び、数を数えるための定義です。
基準の値は [見積の基準](../../reference/estimate-baseline.md)、見積の決まりは [rules/estimate.md](../../rules/estimate.md) にあります。

## レベル

案件のレベル（L1〜L3）は、組織の AWS アカウントの申請（aws_account_form）で決まります。
外部接続、データ、稼働率、RPO の 4 つの軸でそれぞれ段を選び、最も高い段を案件のレベルにします。
個人情報や確定値（請求額など）を扱う案件は、データの軸で L3 になります。
レベルの決め方と必須統制の正は aws_account_form です。このファイルと食い違ったら、aws_account_form に合わせて直します。

| レベル | 構築で増える作業（自分で作る必須統制） | 種別 |
| --- | --- | --- |
| L1 | なし。初期設定、予算、Security Hub は最初から入っている | インフラ（構築・L1） |
| L2 | Multi-AZ、障害アラームの通知、公開するなら WAF 付きの CloudFront か ALB、データストアの削除保護 | インフラ（構築・L2） |
| L3 | L2 に加えて、CMK での暗号化、PITR、データストアをプライベートサブネットだけに置く、VPC エンドポイント、フックの違反への対応。非本番の環境にも掛かる | インフラ（構築・L3） |

L3 の案件は、ふつうは Restricted（統制が最も強い OU）にアカウントを置き、統制の多くが組織から掛かります。グループ外の案件や引き渡す前提の案件は External（その案件を置く OU）に置くので、L3 でも Restricted の統制が組織から掛からず、すべて自分で満たします。External の L3 は、基準から上げる理由にします。

## ブロック

インフラ（構築）は、次の 10 個のブロックから要るものを選び、その数で数えます。

| ブロック | 主なリソースの例 |
| --- | --- |
| 基盤 | アカウント、VPC、サブネット、共通の IAM |
| 公開・配信 | CloudFront、WAF、DNS、SSL 証明書 |
| アプリ実行 | Lambda、ECS、API Gateway、ECR |
| データ保存 | S3、RDS、DynamoDB、Parameter Store |
| 認証 | Cognito、外部 IdP との連携 |
| 定期実行・非同期処理 | EventBridge、Step Functions、SQS |
| 外部連携・通知 | SES、外部 API、SFTP、クライアント証明書 |
| 機械学習・データ分析 | 学習・推論の実行環境、MLflow、Athena |
| 監視・運用 | CloudWatch のアラーム、ログ、バックアップ |
| CI/CD | GitHub Actions、OIDC のロール |

## 例

L3 の案件で、基盤、アプリ実行、データ保存、定期実行・非同期処理、機械学習・データ分析、監視・運用、CI/CD の 7 ブロックを作る場合は、インフラ（構築・L3）を 7 と数え、インフラ（設計）を 1 足します。
